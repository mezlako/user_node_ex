# JIRA-1662: User Model (`src/models/user.model.js`)

## Overview

The User model defines the MongoDB schema and behavior for application users. It is built with Mongoose and exported as the `User` model, which is re-exported from `src/models/index.js` for use in services and controllers.

## Schema Fields

| Field | Type | Required | Default | Notes |
|-------|------|----------|---------|-------|
| `name` | String | Yes | — | Trimmed on save |
| `email` | String | Yes | — | Unique, lowercased, validated with `validator.isEmail` |
| `password` | String | Yes | — | Min 8 chars; must include at least one letter and one number. Marked `private: true` so it is omitted from JSON output |
| `role` | String | No | `'user'` | Must be one of the roles defined in `src/config/roles.js` (`user`, `admin`) |
| `isEmailVerified` | Boolean | No | `false` | Tracks whether the user has verified their email |
| `createdAt` / `updatedAt` | Date | — | Auto | Added by Mongoose `timestamps: true` |

## Validation

- **Email** — Uses the `validator` package. Throws `Invalid email` if the format is invalid.
- **Password** — Enforces minimum length (8) and a regex requiring at least one digit and one letter. Throws `Password must contain at least one letter and one number` on failure.

## Plugins

Two Mongoose plugins are applied to the schema:

1. **`toJSON`** — When a user document is serialized to JSON:
   - Removes `__v`, `createdAt`, `updatedAt`, and any field marked `private` (e.g. `password`)
   - Renames `_id` to `id`

2. **`paginate`** — Adds a static `User.paginate(filter, options)` method for paginated queries (sort, limit, page, populate).

## Instance Methods

### `isPasswordMatch(password)`

Compares a plain-text password against the stored bcrypt hash using `bcrypt.compare`. Returns a `Promise<boolean>`.

## Static Methods

### `isEmailTaken(email, excludeUserId?)`

Checks whether an email is already registered. Optionally excludes a user ID (useful when updating a user's email). Returns a `Promise<boolean>`.

## Middleware

### `pre('save')`

Before a user document is saved, if the `password` field was modified, it is hashed with `bcrypt.hash` (cost factor 8). This runs on create and whenever the password is changed.

## Role Configuration

Roles are imported from `src/config/roles.js`:

- **`user`** — Default role with no special permissions
- **`admin`** — Has rights: `getUsers`, `manageUsers`

The `role` field's `enum` is derived from the keys of that config, so adding a role there automatically constrains valid values on the schema.

## Usage

```js
const { User } = require('../models');

// Create
const user = await User.create({ name, email, password });

// Check email availability
const taken = await User.isEmailTaken('user@example.com');

// Verify password at login
const match = await user.isPasswordMatch('plainTextPassword');

// Paginated list
const result = await User.paginate({}, { page: 1, limit: 10 });
```

## Security Notes

- Passwords are never returned in API responses (`private: true` + `toJSON` plugin).
- Passwords are hashed before persistence; plain text is only held in memory during the request lifecycle.
- Email uniqueness is enforced at the database level via the schema's `unique: true` index.
